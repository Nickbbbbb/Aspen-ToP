# Aspen-ToP 转换链路开发详解

本文档面向维护和二次开发同学，说明项目如何把 Aspen Plus `.bkp` 文件转换为 ToP 软件可导入的 `.hss` 文件。

整体链路：

```text
.bkp 文件
  -> Aspen COM 打开归档文件
  -> 读取 Aspen Tree 中的组分、物性方法、流股、设备、端口和参数
  -> 生成标准化 Aspen JSON
  -> 根据 Template 目录构建 ToP JSON
  -> 调用 export-test/hss_file_tool.py 加密
  -> 输出 .hss 文件
```

## 入口设计

项目支持 Python API 和命令行。

### Python API

对外推荐使用两个函数：

```python
from aspen_to_top import convert_single_bkp, convert_bkp_folder

convert_single_bkp("examples/single_bkp/alkane.bkp")
convert_bkp_folder("examples/batch_bkp")
```

实现位置：

```text
aspen_to_top/api.py
```

`convert_single_bkp(bkp_file)`：

- 输入一个 `.bkp` 文件路径。
- 输出固定放在项目根目录 `output/`。
- 输出文件名和 BKP 同名。
- 默认生成 `output/<name>.hss`、`output/<name>.json`、`output/<name>.extracted.json`。

`convert_bkp_folder(folder)`：

- 输入一个文件夹路径。
- 扫描文件夹第一层的 `*.bkp` 文件。
- 对每个 BKP 调用 `convert_single_bkp`。
- 返回每个文件的转换结果列表。

### 命令行入口

根目录 `main.py` 是命令行入口，流程编排逻辑在：

```text
aspen_to_top/main.py
```

常用命令：

```bash
python main.py examples\single_bkp\alkane.bkp -i
python main.py examples\batch_bkp -i
python main.py a.bkp b.bkp -i
```

`-i` 表示保存 Aspen COM 提取后的中间 JSON，即 `*.extracted.json`。

分步调试命令：

```bash
python main.py case.bkp --extract-only output\case.extracted.json
python main.py --build-only output\case.extracted.json --top-json output\case.json
python main.py --encrypt-only output\case.json -o output\case.hss
python main.py --decrypt output\case.hss output\case.decrypted.json
```

## 第一阶段：读取 `.bkp` 文件

### COM 连接

实现位置：

```text
aspen_to_top/aspen/connector.py
```

核心类：

```python
AspenConnector
```

读取步骤：

1. `pythoncom.CoInitialize()` 初始化线程 COM 环境。
2. `win32com.client.Dispatch("Apwn.Document")` 创建 Aspen Plus COM 文档对象。
3. `aspen.InitFromArchive2(str(bkp_path))` 打开 `.bkp` 归档文件。
4. 通过 `aspen.Tree` 访问 Aspen 流程树。
5. 读取完成后调用 `Close(False)`，并执行 `CoUninitialize()` 释放 COM。

注意事项：

- 该流程需要安装 Aspen Plus 且 COM 可用。
- COM 对象只在 Aspen 读取层使用，读取层向外输出普通 Python dict。
- Aspen 打开失败时，优先检查 BKP 文件、Aspen 版本、COM 权限和进程占用。

### 提取总编排

实现位置：

```text
aspen_to_top/aspen/extractor.py
```

核心类：

```python
AspenExtractor
```

职责：

- `extract_components()` 读取组分 CAS 和名称。
- `extract_method()` 读取 Aspen 物性方法。
- `extract_streams()` 读取流股状态参数。
- `extract_blocks()` 读取模块类型、端口和设备参数。
- `extract_all()` 汇总标准化 Aspen JSON。

输出结构示例：

```json
{
  "components": {
    "cas": ["74-82-8"],
    "name": ["METHANE"]
  },
  "methad": "PENG-ROB",
  "blocks": {
    "FENLV": {
      "type": "Flash2",
      "in_streams": [{"inlet_0": "S9"}],
      "out_streams": [{"vapor_out_0": "S4"}, {"liquid_out_0": "S2"}],
      "params": {}
    }
  },
  "streams": {},
  "stream_topology_map": {},
  "processGraph": {
    "nodes": [],
    "edges": []
  }
}
```

### 组分读取

组分从 Aspen Tree 的 Components 相关路径读取。

读取结果包括：

- CAS 号：用于匹配 `Template/component`、`Template/componentPrivate`。
- 组分名：用于 Source 入口组成的行标题。

ToP 组分 ID 通过以下映射获得：

```text
aspen_to_top/utils/chemical_mapper.py
```

### 流股和拓扑读取

流股信息用于：

1. 构建设备之间的 `processEdges`。
2. 判断哪些流股需要补成 Source 或 Sink 节点。

设备的 `in_streams` 和 `out_streams` 形如：

```json
{
  "in_streams": [{"inlet_0": "S1"}],
  "out_streams": [{"vapor_out_0": "S4"}, {"liquid_out_0": "S2"}]
}
```

左侧是 ToP 端口名，右侧是 Aspen 流股名。

构边规则：

- 同一流股出现在某设备输出和另一设备输入时，生成设备到设备的边。
- 只有输入端的流股补 Source。
- 只有输出端的流股补 Sink。

### 端口读取和映射

实现位置：

```text
aspen_to_top/aspen/ports.py
```

设计思路：

- Aspen 端口名称和数量从 Aspen Tree 读取。
- ToP 端口名称按设备类型规范化。
- 特殊设备通过注册表分发。

注册表：

```python
PORT_PARSERS = {
    "Mixer": parse_mixer_ports,
    "RadFrac": parse_column_ports,
    "SSplit": parse_multi_product_ports,
    "FSplit": parse_multi_product_ports,
    "Sep": parse_multi_product_ports,
}
```

常见端口映射：

- 普通单入口设备：`inlet_0`
- Flash 出口：`vapor_out_0`、`liquid_out_0`
- Source 出口：`outlet_0`
- Sink 入口：`inlet_0`
- Mixer 多入口：`inlet_0`、`inlet_1`
- Splitter 多出口：`outlet_0`、`outlet_1`
- RadFrac 进料：`feed_in_0`、`feed_in_1`
- RadFrac 产品：`top_vapor_out_0`、`top_liquid_out_0`、`bottom_liquid_out_0`
- RadFrac 侧线：`vapor_side_draw_0`、`liquid_side_draw_0`

新增设备时，优先扩展 `ports.py`。

### 设备参数读取

实现目录：

```text
aspen_to_top/aspen/blocks/
```

每个设备类型一个 extractor，例如：

```text
flash.py
pump.py
heater.py
column.py
heatx.py
mixer.py
splitter.py
component_splitter.py
```

注册位置：

```text
aspen_to_top/aspen/extractor.py
```

每个 extractor 的职责：

- 读取 Aspen Tree。
- 返回标准化 `params`。
- 不引用 ToP 模板。
- 不生成 ToP 节点 ID。

Flash 参数读取示例：

```python
base = fr"\Data\Blocks\{block_name}\Input"
{
    "SPEC_OPT": get_prop(tree, fr"{base}\SPEC_OPT"),
    "system_pressure": get_prop(tree, fr"{base}\PRES"),
    "system_temperature": get_prop(tree, fr"{base}\TEMP"),
    "system_vapor_molar_fraction": get_prop(tree, fr"{base}\VFRAC"),
    "system_heat_duty": get_prop(tree, fr"{base}\DUTY"),
}
```

### 坐标读取

实现位置：

```text
aspen_to_top/utils/layout.py
```

坐标从 `.bkp` 原始内容中按文本片段解析：

```text
ID: <target_id> ... At <x> <y>
```

关键函数：

```python
extract_coords_from_bkp(file_path, target_id)
```

规则：

- 设备节点用 Aspen block 名读取坐标。
- Source/Sink 节点用流股名读取坐标。
- 坐标写入 ToP `processNodes[*].x` 和 `processNodes[*].y`。

## 第二阶段：构建 ToP JSON

### 总编排

实现位置：

```text
aspen_to_top/converter/json_builder.py
```

核心类：

```python
TopJsonBuilder
```

构建顺序：

1. 加载 `Template/final_template.json`。
2. 生成 projectId、processId、componentGroupId。
3. 构建 `omProject`。
4. 构建 `omProcessArchive`。
5. 构建 `omProcessGraph`。
6. 构建组分、组分组、组分明细和物性方法列表。

### 模板加载

实现位置：

```text
aspen_to_top/converter/templates.py
```

模板来源：

```text
Template/final_template.json
Template/processNodes/
Template/nodeProperties/
Template/processEdges_connetion.json
Template/component/
Template/componentPrivate/
Template/componentGroupPrivateList/
Template/methodPrivateList/
```

关键约束：

- 每次加载模板都返回深拷贝。
- 多个节点不共享同一个 dict。

### ID 生成

实现位置：

```text
aspen_to_top/converter/ids.py
```

ToP 节点 ID 格式：

```text
<类型前缀>_<随机8位hex>_<ToP节点类型名><计数>
```

示例：

```text
598fddf9_c9e5caf8_Flash1
54a52706_4a08aeef_Source1
ff1924d5_9c686914_Sink1
```

同一次转换中必须保持：

- `processNodes[*].id` 唯一。
- `processEdges[*].source.cell` 能在节点 ID 中找到。
- `processEdges[*].target.cell` 能在节点 ID 中找到。

### 组分和物性方法

实现位置：

```text
aspen_to_top/converter/assets_builder.py
```

负责构建：

- `componentPrivateList`
- `componentGroupPrivateList`
- `componentGroupDetailList`
- `methodPrivateList`

数据流：

```text
Aspen CAS 号
  -> ChemicalMapper 映射 ToP componentId
  -> Template/component 与 Template/componentPrivate
  -> ToP 组分列表
```

### 流程图构建

实现位置：

```text
aspen_to_top/converter/graph_builder.py
```

负责构建：

```text
omProcessGraph
  processNodes
  processEdges
```

注意：最终 ToP JSON 中，`processNodes` 和 `processEdges` 是 JSON 字符串。

调试时先反序列化：

```python
nodes = json.loads(data["omProcessGraph"]["processNodes"])
edges = json.loads(data["omProcessGraph"]["processEdges"])
```

节点构建逻辑：

1. 遍历 Aspen blocks。
2. 每个 block 生成一个 ToP 设备节点。
3. 加载设备节点模板。
4. 加载设备 `nodeProperties` 模板。
5. 用 `property_fillers.py` 填充设备参数。
6. 从 BKP 读取坐标。
7. 记录 `block_name -> node_id` 映射。

边构建逻辑：

1. 按 Aspen 流股名匹配输出端和输入端。
2. 创建 `processEdges`。
3. `source.cell` 写上游节点 ID。
4. `source.port` 写上游 ToP 端口名。
5. `target.cell` 写下游节点 ID。
6. `target.port` 写下游 ToP 端口名。
7. `attrs.label` 写 Aspen 流股名。

### 设备属性填充

实现位置：

```text
aspen_to_top/converter/property_fillers.py
```

设计目标：

- Aspen 读取层负责读参数。
- ToP 构建层负责填模板。
- 每种设备一个填充函数。
- 用注册表分发。

注册表：

```python
PROPERTY_FILLERS = {
    "Flash2": fill_flash,
    "Heater": fill_heater,
    "Pump": fill_pump,
    "RadFrac": fill_column,
}
```

## 第三阶段：加密成 HSS

### 外部工具

HSS 加密工具：

```text
export-test/hss_file_tool.py
```

约束：

- 不修改该文件。
- 本项目通过适配层调用它。

### 适配层

实现位置：

```text
aspen_to_top/encryption/hss_tool.py
```

核心类：

```python
HssTool
```

主要职责：

1. 动态加载 `export-test/hss_file_tool.py`。
2. 兼容外部工具对 `Crypto.Util.Padding` 的导入方式。
3. 调用外部工具的加密函数。
4. 提供解密函数用于排查。

加密流程：

```text
ToP JSON 文件
  -> HssTool.encrypt(json_path, hss_path)
  -> export-test/hss_file_tool.py
  -> 生成 .hss
```

## 调试建议

### 检查 HSS 中内容

```bash
python main.py --decrypt output\case.hss output\case.decrypted.json
```

比较：

```text
output\case.json
output\case.decrypted.json
```

### 检查边引用

```python
import json

data = json.load(open("output/case.json", encoding="utf-8"))
nodes = json.loads(data["omProcessGraph"]["processNodes"])
edges = json.loads(data["omProcessGraph"]["processEdges"])

node_ids = {node["id"] for node in nodes}
for edge in edges:
    assert edge["source"]["cell"] in node_ids, edge
    assert edge["target"]["cell"] in node_ids, edge
```

### 检查端口引用

```python
for edge in edges:
    for side in ("source", "target"):
        node = next(node for node in nodes if node["id"] == edge[side]["cell"])
        ports = [
            virtual["id"]
            for group in node["ports"]
            for virtual in group["relateVirtualPortList"]
        ]
        assert edge[side]["port"] in ports, edge
```

### 检查 Source/Sink 坐标

```python
for node in nodes:
    if node["type"] in ("Source", "Sink"):
        print(node["data"]["label"], node["x"], node["y"])
```

## 维护边界

- Aspen COM 路径读取只放在 `aspen/`。
- ToP 模板字段填充只放在 `converter/`。
- HSS 加密只放在 `encryption/`。
- 坐标读取和后处理工具放在 `utils/`。
- 新设备通过注册表扩展。
- `export-test/hss_file_tool.py` 保持独立。
- `Template/` 是运行时依赖。
