# Aspen-ToP 项目总览

## 项目目标

Aspen-ToP 用于把 Aspen Plus `.bkp` 文件转换为 ToP 软件可导入编辑的 `.hss` 文件。

转换链路：

```text
Aspen .bkp
  -> Aspen COM 读取
  -> 标准化 Aspen JSON
  -> ToP JSON
  -> export-test 加密工具
  -> ToP .hss
```

生成 `.hss` 时会保留最终 ToP JSON，便于检查 ToP 导入失败时的结构问题。

## 入口文件

```text
main.py
aspen_to_top/main.py
aspen_to_top/api.py
```

- `main.py`: 根目录命令行入口。
- `aspen_to_top/main.py`: 转换流程编排器，负责提取、构建和加密。
- `aspen_to_top/api.py`: 对外 Python 接口，提供单文件转换和文件夹批量转换函数。

## 核心目录

```text
aspen_to_top/
  main.py                  转换流程编排
  api.py                   Python 对外接口
  aspen/                   Aspen COM 读取层
  converter/               ToP JSON 构建层
  encryption/              HSS 加密适配层
  utils/                   坐标、组分映射等工具

Template/                  ToP JSON 模板
export-test/               外部 HSS 加密工具
examples/                  单文件和批量转换示例
docs/                      项目文档
```

## Aspen 读取层

目录：

```text
aspen_to_top/aspen/
```

职责：

- 打开 Aspen Plus COM。
- 从 Aspen Tree 读取全局配置、组分、物性方法、流股、设备、端口和参数。
- 输出标准化 Aspen JSON。
- 不生成 ToP 模板字段。

关键文件：

- `connector.py`: 打开和关闭 Aspen Plus COM。
- `extractor.py`: 读取流程总编排。
- `ports.py`: Aspen 端口到 ToP 端口名的映射规则。
- `blocks/*.py`: 各设备参数读取器。

设备参数读取按设备拆分，例如：

```text
blocks/flash.py
blocks/pump.py
blocks/column.py
blocks/heatx.py
```

端口规则通过注册表维护：

```python
PORT_PARSERS = {
    "Mixer": parse_mixer_ports,
    "RadFrac": parse_column_ports,
    "SSplit": parse_multi_product_ports,
    "FSplit": parse_multi_product_ports,
    "Sep": parse_multi_product_ports,
}
```

## ToP JSON 构建层

目录：

```text
aspen_to_top/converter/
```

职责：

- 把标准化 Aspen JSON 转成 ToP JSON。
- 生成 `omProject`、`omProcessArchive`、`omProcessGraph`。
- 生成 `processNodes`、`processEdges`。
- 生成组分、组分组和物性方法。

关键文件：

- `json_builder.py`: ToP JSON 构建总编排。
- `project_builder.py`: 构建项目元信息。
- `graph_builder.py`: 构建节点、边和 Source/Sink 属性。
- `assets_builder.py`: 构建组分和物性方法。
- `property_fillers.py`: 按设备类型填充 `nodeProperties`。
- `templates.py`: 加载模板并返回深拷贝。
- `ids.py`: 生成 ToP ID。

## HSS 加密层

目录：

```text
aspen_to_top/encryption/
```

职责：

- 调用外部 `export-test/hss_file_tool.py`。
- 保持外部加密工具代码独立。

关键文件：

```text
aspen_to_top/encryption/hss_tool.py
export-test/hss_file_tool.py
```

## 坐标逻辑

坐标从 `.bkp` 文件中读取，逻辑在：

```text
aspen_to_top/utils/layout.py
```

规则：

- 普通设备节点按 Aspen block 名读取坐标。
- Source/Sink 节点按流股名读取坐标，例如 `S1`、`S2`、`S7`。
- 坐标写入 ToP JSON 的 `processNodes[*].x/y`。

## 支持的 Aspen 模块

代码中配置了以下 Aspen 模块到 ToP 模块的读取和构建逻辑：

- `Flash2`
- `Heater`
- `Compr`
- `Pump`
- `Valve`
- `Mixer`
- `SSplit`
- `FSplit`
- `HeatX`
- `RadFrac`
- `Sep`
- `RecycleBreaker`
- `RStoic`

## 设计约束

- 不修改 `export-test/hss_file_tool.py`。
- Aspen COM 路径读取放在 `aspen/`。
- ToP 模板字段填充放在 `converter/`。
- 模板加载必须返回深拷贝，避免多个节点共用同一个 dict。
- 生成 HSS 时保留最终 ToP JSON。
- 新设备优先通过 extractor、port parser、property filler 注册表扩展。
